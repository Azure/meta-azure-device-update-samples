# adu-update-image-v4 demo payload

`agent-payload-v4.bin` is a 4 MiB deterministic, high-entropy (incompressible)
blob deployed to `/opt/adu-demo/agent-payload-v4.bin` on the v4 rootfs.

## Why

v1, v2, and v3 update images differ only in `/etc/adu-version` (8 bytes), so
the v1→v2 / v2→v3 deltas are artificially small (~1.4 MB out of 100 MB SWU =
98.6 % savings — looks rigged in demos). v4 introduces realistic-sized content
delta (~3–5 MB) so the "delta vs full" comparison is credible for customer
demos.

## What

A 4 MiB blob whose bytes are reproducibly generated. Because the bytes are
near-uniform random, gzip/zstd cannot compress them, so:

- `adu-update-image-v4.swu` is ~104 MB (same order as v1/v2/v3).
- `adu-delta-v3-to-v4.diff` is ~4 MB (the blob is "new" content; the diff
  encoder must include it verbatim).

## How (regeneration recipe)

This file is checked in. If you ever need to regenerate it identically:

```sh
python3 -c "import random; open('agent-payload-v4.bin','wb').write(random.Random(42).randbytes(4*1024*1024))"
```

SHA256 (expected): `81f1365aec00473e2ae8849aa9f1f5e268c6c1f195e90412e6643fd7757128b6`

Do not edit this file in-place; regenerate from the recipe above.

## Disclaimer

This payload is a *synthetic demo artifact*. It is not an Azure Device Update
agent, kernel module, or any real software. It exists only to make the v3→v4
delta non-trivially sized for "delta vs full" timing demos.
